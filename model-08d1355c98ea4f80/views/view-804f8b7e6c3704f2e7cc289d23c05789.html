Library Membership Mgt ()
## Purpose This process handles the end-to-end lifecycle of library membership, from initial application through credential issuance. It ensures that only verified and eligible individuals gain access to library resources, supporting institutional security and service personalisation. ## Roles - Library Staff (userTask) - System (serviceTask, scriptTask) - Applicant (external) ## Upstream Inputs - Personal Data (name, contact, ID) - Eligibility Criteria (student status, faculty ID, external membership proof) ## Downstream Outputs - Verified Member Record - Access Credentials (barcode, PIN, digital ID) - Notification to Applicant ## Key Decisions - Eligibility Check: Is the applicant eligible for the requested membership type? - Data Validation: Are all required personal data fields complete and valid? ## Exception Paths - Incomplete or invalid personal data: Applicant is asked to resubmit corrected information. - Eligibility criteria not met: Application is rejected with a reason notification. - System failure during credential generation: Manual intervention by Library Staff to issue credentials. ## Step Walkthrough 1. Receive Application: Library Staff collects the membership application with personal data and eligibility documents. 2. Validate Personal Data: System checks that all required fields are complete and correctly formatted; if invalid, the applicant is asked to resubmit. 3. Check Eligibility: System verifies the applicant meets the criteria for the requested membership type; if not, the application is rejected. 4. Create Member Record: System creates a verified member record in the library database. 5. Generate Access Credentials: System generates a unique barcode and PIN for the new member. 6. Notify Member: System sends a notification to the applicant with their membership details and credentials. Steps: 1. Receive Application: The applicant submits a membership application form along with supporting personal data and eligibility documents. Library Staff reviews the submission for completeness and enters the data into the system. 2. Validate Personal Data: The system automatically validates the submitted personal data against predefined rules (e.g., name format, ID number pattern, contact details). If validation fails, the applicant is asked to resubmit corrected information. 3. Check Eligibility: The system cross-references the applicant's data with institutional databases (student registry, faculty directory, external membership records) to confirm eligibility. If criteria are not met, the application is rejected. 4. Create Member Record: Upon successful eligibility check, the system creates a new member record with all verified personal data, membership type, and effective dates. The record is stored in the library's member database. 5. Generate Access Credentials: The system generates a unique membership barcode and a secure PIN for the member. These credentials are linked to the member record and will be used for library access and borrowing. 6. Notify Member: The system sends an automated notification (email or SMS) to the applicant containing their membership ID, barcode, PIN, and instructions for using library services. 7. Request Resubmission: When personal data validation fails, the system notifies the applicant with details of the errors and requests corrected information. The applicant must resubmit a corrected application. 8. Reject Application: When eligibility criteria are not met, the system sends a rejection notification to the applicant explaining the reason (e.g., not a current student, expired faculty ID). The process ends for this applicant.
