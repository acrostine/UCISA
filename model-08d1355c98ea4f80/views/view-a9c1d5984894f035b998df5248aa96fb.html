End User Computing ()
## Purpose End User Computing provides and manages computing devices, tools, and support services for students, faculty, and staff. It consumes hardware and software resources, user requests, and technical standards, delivering reliable access to computing environments and applications. This process empowers the campus community to perform academic, research, and administrative tasks efficiently and securely. ## Roles - Service Desk Analyst: Receives and triages user requests - IT Support Technician: Provisions and configures devices - IT Asset Manager: Verifies eligibility and manages inventory - Quality Assurance Specialist: Reviews configured devices for compliance - System: Automated provisioning and notification services ## Upstream Inputs - User Request - Hardware and Software Resources - Technical Standards - Asset Inventory Data ## Downstream Outputs - Provisioned Device - User Notification - Asset Record Update - Support Ticket ## Key Decisions - Eligibility verification: Is the user eligible for the requested device? - Configuration review: Does the configured device meet technical standards? - Deployment method: Will the device be shipped or picked up? ## Exception Paths - Ineligible user: Request is rejected with explanation - Configuration non-compliance: Device is sent for rework and re-review - Hardware shortage: User is placed on backorder queue ## Step Walkthrough 1. Receive User Request: The process begins when a student, faculty, or staff member submits a request for a computing device or software. The Service Desk Analyst logs the request into the ticketing system, categorizes it by device type and urgency, and gathers initial information including user identity, department, and requested specifications. 2. Verify User Eligibility: The IT Asset Manager reviews the user's profile against institutional policies, funding sources, and device entitlement rules. This step ensures that only authorized users receive institutional computing resources and that the request aligns with budget and lifecycle replacement schedules. 3. Provision Device: Based on the approved request, the IT Support Technician retrieves the appropriate device from inventory, installs the standard operating system image, applies security patches, and installs required software applications. The device is configured to connect to campus network and services. 4. Review Configuration: The Quality Assurance Specialist performs a compliance check on the configured device, verifying that all required software is installed, security settings are applied, and the device meets institutional technical standards. Any deviations are documented for remediation. 5. Deploy Device: Once the device passes quality review, the IT Support Technician prepares it for deployment. This includes packaging, labeling, and arranging for either on-campus pickup or shipping to the user's location. The asset record is updated to reflect the assigned user and deployment date. 6. Notify User: An automated email or portal notification is sent to the user confirming device availability, providing setup instructions, and including contact information for further support. The support ticket is updated to 'Completed' status. 7. Resolve Configuration Issues: When the configuration review identifies non-compliance issues, the IT Support Technician reworks the device by applying missing configurations, reinstalling software, or correcting security settings. The device is then resubmitted for another quality review cycle. 8. Reject Ineligible Request: When the eligibility check determines the user is not entitled to the requested device, the Service Desk Analyst documents the reason, closes the support ticket, and sends a notification to the user explaining the decision and any alternative options available.
