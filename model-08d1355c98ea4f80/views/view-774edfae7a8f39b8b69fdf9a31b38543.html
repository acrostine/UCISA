## Purpose This process ensures the integrity, quality, and availability of institutional data assets by managing their collection, storage, and maintenance. It consumes raw data from academic and administrative sources and produces validated, consistent datasets that underpin effective operations, reporting, and research activities. ## Roles - Data Steward: responsible for data validation and quality oversight - Data Analyst: performs data profiling and cleansing - System Administrator: manages storage infrastructure and access - System: automated validation and storage services ## Upstream Inputs - Raw Data Feeds: incoming data from academic and administrative source systems - Data Source Metadata: schema and format definitions for each feed ## Downstream Outputs - Validated Datasets: cleansed and standardised data ready for use - Data Quality Report: summary of validation results and issues found - Archived Data: historical snapshots retained for compliance ## Key Decisions - Whether raw data meets quality thresholds for acceptance - Whether data quality issues require rework or can be accepted with notes - Which storage tier to assign based on data criticality and access frequency ## Exception Paths - If validation fails, the data is sent back for rework with a detailed error report - If storage allocation fails, an alert is raised to the System Administrator for manual intervention ## Step Walkthrough 1. Collect Raw Data: Data feeds from academic and administrative source systems are ingested into a staging area. The system logs receipt metadata including timestamp, source identifier, and file size. Any transmission errors are captured for immediate notification. 2. Validate Data Structure: The system compares the structure of each staged data file against the schema defined in the Data Source Metadata. Fields are checked for correct data types, required presence, and allowed value ranges. Non-conforming records are flagged with specific error codes. 3. Profile Data Quality: The Data Analyst executes automated profiling scripts that calculate metrics such as null rates, duplicate counts, value distributions, and cross-field consistency. The results are compiled into a preliminary quality scorecard for review. 4. Assess Quality Threshold: The Data Steward examines the Quality Profile Report and compares each metric against predefined thresholds. A decision is made to either accept the data as-is, accept with documented exceptions, or reject it for rework. This step is the primary quality gate. 5. Remediate Data Issues: The Data Steward works with the source system owner to identify root causes of quality failures. Corrections are applied at the source or through transformation rules, and the corrected data is resubmitted to the staging area for re-validation. 6. Standardise and Transform: The system applies a set of transformation rules including date format normalisation, code value mapping, string trimming, and cross-reference resolution. The output is a clean, standardised dataset ready for storage. 7. Store in Repository: The system writes the standardised dataset to the appropriate storage repository based on data criticality and access frequency. Access controls are applied, and a storage confirmation record is generated. 8. Generate Quality Report: The system compiles a final Data Quality Report that includes the original validation results, quality profile metrics, any issues remediated, and the final dataset characteristics. This report is archived alongside the dataset for audit purposes.
