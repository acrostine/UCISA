## Purpose Identity and Access Management (IAM) controls authentication, authorisation, and user account lifecycle to secure institutional systems and data. It consumes identity data and access policies, producing verified access credentials and audit logs. This process protects sensitive information, ensures compliance with regulations, and facilitates seamless yet secure resource access. ## Roles - Access Requestor: Submits initial access request - Identity Analyst: Reviews and validates identity data - Access Approver: Authorises access based on policy - System Administrator: Provisions accounts and credentials - Auditor: Reviews access logs for compliance ## Upstream Inputs - Identity Data (employee records, student records) - Access Policies (role definitions, entitlement rules) - Access Request Form ## Downstream Outputs - Verified Access Credentials - Provisioned User Account - Access Audit Log ## Key Decisions - Is identity data complete and valid? - Does the requested access comply with policy? - Should access be modified or revoked during review? ## Exception Paths - Incomplete or invalid identity data triggers rework and resubmission - Non-compliant access request is rejected with notification - Suspicious account activity escalates to security incident handling ## Step Walkthrough 1. Receive Access Request: The process begins when an Access Requestor completes and submits an access request form. The form includes personal identity data (name, department, role) and the specific systems or resources requested. The request is captured in the IAM system for processing. 2. Validate Identity Data: The Identity Analyst compares the identity data from the request against authoritative HR or student records. They verify name, department, role, and employment status. If data is incomplete or mismatched, the request is flagged for rework. 3. Review Access Policy: The Identity Analyst checks the requested access level against the organisation's access policies and role definitions. They confirm that the access aligns with the user's role and least-privilege principles. Any policy violation is noted for rejection. 4. Approve Access Request: The Access Approver reviews the validated identity data and policy compliance result. They make a final decision to approve or reject the request. If approved, the request proceeds to provisioning; if rejected, the requestor is notified with a reason. 5. Provision User Account: The System Administrator uses the IAM system to create a new user account or update an existing one. They assign the approved roles, groups, and entitlements. The account is configured with appropriate access controls and policies. 6. Issue Credentials: The IAM system generates and securely delivers the access credentials (e.g., password, token, certificate) to the user. Credentials are sent through a secure channel such as encrypted email or self-service portal. The user is notified to activate their account. 7. Log Access Event: The IAM system automatically logs all provisioning actions, including user identity, access granted, timestamp, and approving authority. This log is stored in a tamper-evident audit trail for compliance and monitoring purposes. 8. Conduct Periodic Review: The Auditor periodically examines the access audit logs and current account statuses. They look for unauthorised access attempts, expired entitlements, or accounts that should be deactivated. Findings are documented for remediation or account modification.
