## Purpose Application Lifecycle Management governs the end-to-end development, deployment, and maintenance of software applications supporting academic and administrative functions. It consumes user requirements, technical specifications, and feedback, producing stable, secure, and updated applications. This process ensures alignment of software capabilities with institutional goals, enhancing operational efficiency and user satisfaction. ## Roles - Business Analyst: Gathers and documents user requirements - Application Manager: Reviews and prioritises requirements, oversees lifecycle - Developer: Builds and tests application features - Quality Assurance Analyst: Validates application against specifications - System Administrator: Deploys and maintains applications in production ## Upstream Inputs - User Requirements - Technical Specifications - User Feedback - Change Requests ## Downstream Outputs - Deployed Application - Updated Application - Release Notes - Maintenance Reports ## Key Decisions - Whether to approve or reject a requirement for development - Whether the application passes quality validation - Whether to deploy the application to production - Whether to escalate critical issues for immediate remediation ## Exception Paths - Rejected requirements are returned to the Business Analyst for clarification or rework - Failed validation triggers a rework loop back to development - Critical production issues are escalated for urgent remediation ## Step Walkthrough 1. Collect Requirements: The Business Analyst engages with academic and administrative stakeholders to collect detailed user requirements and technical specifications. This step captures functional needs, performance expectations, and integration constraints. All inputs are documented in a standardised format for review. 2. Review Requirements: The Application Manager reviews the documented requirements against institutional goals, technical feasibility, and resource availability. Requirements are assessed for clarity, completeness, and priority. A recommendation is prepared for approval or rejection. 3. Approve Requirements: The Application Manager makes a final decision on each requirement. Approved requirements are prioritised and queued for development. Rejected requirements are returned with feedback for clarification or rework. 4. Develop Application: The Developer implements the approved requirements, writing code and integrating components. Development follows established coding standards and version control practices. The completed build is prepared for validation. 5. Validate Application: The Quality Assurance Analyst executes test cases covering functional, performance, and security criteria. Results are documented, and any defects are logged. The application either passes validation or is returned for rework. 6. Deploy Application: The System Administrator deploys the validated application build to the production environment following change management procedures. Deployment is verified, and release notes are published. The application becomes available to end users. 7. Monitor and Maintain: The System Administrator continuously monitors application health, performance metrics, and user feedback. Routine maintenance updates and patches are applied. Issues are logged for resolution. 8. Address Issues: The Developer reviews the issue log and resolves defects or implements minor enhancements. Critical issues are escalated for immediate remediation. Resolved changes are fed back into the development cycle.
