It provides a controlled workflow from request initiation through to final storage, with built-in quality checks and exception handling. ## Roles - Data Steward: Initiates and oversees the collection request - Data Analyst: Identifies sources and executes data gathering - System: Automates validation rules and storage operations - Quality Reviewer: Validates collected data against quality criteria ## Upstream Inputs - Collection Request from business units or compliance mandates - Source Metadata from institutional data catalog - Third-party data feeds from external providers - Survey responses from academic and administrative surveys ## Downstream Outputs - Validated Data Set stored in the institutional data warehouse - Collection Report summarising source, volume, and quality results - Exception Log for any data that failed validation ## Key Decisions - Are all required sources identified and accessible? - Does the collected data meet defined quality thresholds? - Should failed data be re-collected or escalated? ## Exception Paths - If data fails validation, it is sent to a remediation step for re-collection or correction, then re-validated. - If remediation is not possible, the exception is logged and escalated to the Data Steward. ## Step Walkthrough 1. Receive Collection Request: The Data Steward receives a collection request from a business unit or compliance mandate. The request is logged in the collection management system with details on scope, required sources, and deadlines. This step establishes the formal trigger for the process. 2. Identify Data Sources: The Data Analyst reviews the collection request and consults the institutional data catalog to identify all required sources. This includes academic systems, administrative databases, survey platforms, and third-party providers. Access permissions and data availability are confirmed. 3. Gather Data from Sources: The Data Analyst performs the actual data extraction from each identified source. This may involve running queries on academic systems, downloading survey results, or receiving feeds from third-party providers. Raw data is compiled into a staging area for validation. 4. Validate Collected Data: The Quality Reviewer applies validation rules to the raw data, checking for completeness, accuracy, and consistency with source metadata. Any discrepancies or missing values are flagged. This step determines whether the data is fit for storage and use. 5. Store Validated Data: The System automatically writes the validated data set to the institutional data warehouse. Metadata tags are applied for traceability. The storage operation is logged for audit purposes. 6. Notify Requestor of Completion: The System generates and sends a notification to the original requestor. The notification includes a collection report summarising sources, volume, and quality results. The process ends here for the standard path. 7. Remediate Data Issues: The Data Analyst reviews the validation exception report and takes corrective action. This may involve re-extracting data from the source, correcting manual entry errors, or requesting updated feeds from third parties. The corrected data is then re-submitted for validation.
